# RSB-0001 — Semantic Invariance: Positive Test
# Benchmark for: CHR-0001
# Category: Positive
# Version: 1.0 | Status: ACTIVE

---

## Purpose

Test that two conformant EKS implementations produce identical answers
for all queries in this benchmark when given the same canonical input graph.

This benchmark covers: CHR-0001 (typed relation semantic invariance).
It covers ONLY this hypothesis. A separate benchmark is required for
any additional hypothesis.

---

## Queries (Conformance Suite Q — RSB-0001)

Each implementation must answer all 10 queries. Answers must be
identical across conformant implementations for the benchmark to pass.

```yaml
queries:

  Q01:
    description: "Direct parent lookup"
    query: "What is the parent of SULAI?"
    expected_answer:
      entity: LUXIONEX
      relation_type: IS_CHILD_OF

  Q02:
    description: "Direct children lookup"
    query: "What entities are IS_CHILD_OF children of LUXIONEX?"
    expected_answer:
      entities: [SULAI]

  Q03:
    description: "IS_PART_OF lookup"
    query: "What is SULAI-TAC a part of?"
    expected_answer:
      entity: SULAI
      relation_type: IS_PART_OF

  Q04:
    description: "Relation type discrimination"
    query: "Is the relation from SCSS to RAHMA IS_CHILD_OF?"
    expected_answer: false
    note: "SCSS is RELATED_TO RAHMA, not IS_CHILD_OF. Must discriminate."

  Q05:
    description: "Relation type identification"
    query: "What is the relation type from SCSS to RAHMA?"
    expected_answer: RELATED_TO

  Q06:
    description: "Transitive ancestor lookup (depth 2)"
    query: "Is SULAI-TAC a descendant of LUXIONEX via IS_PART_OF or IS_CHILD_OF?"
    expected_answer: true
    note: "SULAI-TAC IS_PART_OF SULAI IS_CHILD_OF LUXIONEX"

  Q07:
    description: "Source field preservation"
    query: "What is the source of the relation R001?"
    expected_answer: CANONICAL_ARCHITECTURE

  Q08:
    description: "Confidence field preservation"
    query: "What is the confidence of entity E002?"
    expected_answer: 1.0

  Q09:
    description: "Negative lookup — non-existent relation"
    query: "Is SULAI-TAC IS_CHILD_OF LUXIONEX?"
    expected_answer: false
    note: "The path exists transitively but the DIRECT relation type is IS_PART_OF to SULAI."

  Q10:
    description: "Entity type lookup"
    query: "What is the entity_type of RAHMA?"
    expected_answer: GOVERNANCE_SYSTEM
```

## Pass Criteria

A benchmark run PASSES if and only if:
- All 10 queries produce the expected answer
- The implementation being tested has no knowledge of the expected answers
  prior to execution (independence requirement)
- The run is fully documented with the artifacts listed below

A benchmark run FAILS if:
- Any single query produces a different answer than expected
- The independence requirement cannot be confirmed

## Relationship to CHR-0001

This benchmark provides Positive evidence for CHR-0001.
A passing run, independently reproduced, contributes one unit toward
the minimum_reproductions requirement (CHR-0001 requires 2).

A failing run triggers investigation before it is recorded as Negative
evidence — a single implementation defect is not a refutation.
Refutation requires confirmed conformant intent from the implementor.
